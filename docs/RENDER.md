# Deploy on Render

This repo ships a [Render Blueprint](https://render.com/docs/blueprint-spec) (`render.yaml`) with:

| Service | Name | Dockerfile | Description |
|---------|------|------------|-------------|
| PostgreSQL | `pawankalyanfan-db` | — | Database (or use [Neon](https://neon.tech) instead) |
| Web (Docker) | `pawankalyanfan-api` | `Dockerfile.backend` | API gateway + all microservices |
| Web (Docker) | `pawankalyanfan-web` | `Dockerfile.web` | Next.js frontend |

## Quick deploy

1. Push this repo to GitHub.
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**.
3. Connect the repository and apply `render.yaml`.

**If you see `open Dockerfile: no such file or directory`:** the service was created without the blueprint paths. Either redeploy from the blueprint, or in each service go to **Settings → Build & Deploy → Dockerfile Path** and set:
   - API: `Dockerfile` (or `Dockerfile.backend`)
   - Web: `Dockerfile.web`
4. After the API service is live, open **Shell** on `pawankalyanfan-api` (or run locally against prod `DATABASE_URL`):

   ```bash
   npm run db:seed
   ```

5. On `pawankalyanfan-web`, set `NEXT_PUBLIC_SITE_URL` to `https://<your-web-hostname>` if the auto value is missing the `https://` prefix (Render host only).
6. Open the `pawankalyanfan-web` URL.

## Environment variables

### `pawankalyanfan-api`

| Variable | Required | Notes |
|----------|----------|--------|
| `DATABASE_URL` | Yes | From Render Postgres or Neon (pooled) |
| `DIRECT_URL` | Yes | Neon direct URL; for Render Postgres use same as `DATABASE_URL` |
| `JWT_SECRET` | Yes | Auto-generated by blueprint |
| `OPENROUTER_API_KEY` | No | AI chat |
| `RAZORPAY_*` | No | Payments |

### `pawankalyanfan-web`

| Variable | Required | Notes |
|----------|----------|--------|
| `NEXT_PUBLIC_API_URL` | Yes | `/api` (proxied to gateway via Next rewrites) |
| `API_GATEWAY_HOST` | Yes | Set from `pawankalyanfan-api` (hostname only) |
| `NEXT_PUBLIC_SITE_URL` | Yes | Your web service public URL (`https://...`) |

## Using Neon instead of Render Postgres

1. Remove or skip the `databases` block in `render.yaml`.
2. On `pawankalyanfan-api`, set:
   - `DATABASE_URL` — pooled Neon URL
   - `DIRECT_URL` — direct Neon URL (for Prisma)

## Local production-like test

```bash
# Terminal 1 — API stack (Docker)
docker build -f Dockerfile.backend -t pkf-api .
docker run --rm -p 4000:4000 --env-file .env -e PORT=4000 pkf-api

# Terminal 2 — Web (Docker)
docker build -f Dockerfile.web -t pkf-web --build-arg API_GATEWAY_HOST=localhost:4000 .
docker run --rm -p 3000:3000 -e PORT=3000 -e API_GATEWAY_HOST=host.docker.internal:4000 -e NEXT_PUBLIC_SITE_URL=http://localhost:3000 pkf-web
```

On Windows Docker Desktop, use `host.docker.internal` instead of `localhost` inside the web container.

## Health checks

- API: `GET https://<api-host>/api/health`
- Web: `GET https://<web-host>/`

## Notes

- Free/starter instances **spin down** after inactivity; first load may take 30–60s.
- The API runs all microservices in one container to reduce cost (see `Dockerfile.backend`).
- Wallpaper images are served from `apps/web/public` (included in the web Docker build).
